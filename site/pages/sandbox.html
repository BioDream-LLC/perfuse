What it is

A public Perfuse server playing a health plan, the "Perfuse Test Plan". It runs the same code as a real deployment, with test data only: no real plan, member or person.

Why it exists

No live payer lets unknown code near its production endpoints, and you cannot test an EHR's prior authorization without someone on the other side.

How you use it

Sign with the sandbox's published keys, call the endpoints below, or run the example script, which does the whole round and prints what the plan answered.

  • Da Vinci CRD 2.2.1, DTR 2.2.0 and PAS 2.2.1, the same server Inferno's suites pass against (results)
  • SMART Backend Services and SMART App Launch, so your client authorizes as it would with a real payer
  • Approve, pend, deny and "documentation needed" answers, chosen by the order's code
# Node 18 or newer, nothing to install
curl -O https://perfuse.health/sandbox/try-sandbox.mjs
node try-sandbox.mjs

1. token: ok, scopes system/*.rs system/Claim.c
2. CRD cards:
   - Home oxygen equipment: covered, prior authorization required
   - system action: update Record the coverage information on the order
3. DTR package: 200 Questionnaire "Home oxygen documentation (test plan)", QuestionnaireResponse
4. PAS $submit: 200 outcome complete, review action A1, authorization PA-9B1579A6

The script is about 100 lines you can read: a token, the CRD order-sign hook for a portable oxygen system, the DTR questionnaire package for the order CRD returned, and the PAS guide's own referral example submitted. Review actions are X12's: A1 approved, A3 denied, A4 pended, A6 modified.

Signing in

Published test keys, so there is nothing to ask for

The sandbox has a client whose private keys are public on purpose, as Inferno publishes its own. Everything they reach is invented, and the client may read everything but write only what CRD, DTR and PAS send.

  • Backend Services token: client id sandbox, a client_credentials request with a JWT assertion signed by one of the keys (ES384 or RS384), audience the token endpoint
  • CRD hook calls: a CDS Hooks JWT with issuer https://perfuse.health/sandbox and audience the service's URL, for example https://test.perfuse.health/cds-services/crd-order-sign
  • Public keys: /sandbox/jwks.json. Private keys: /sandbox/private-jwks.json
  • Your own client (your JWKS URL, or redirect URIs for an app launch): open an issue and we add it

Plainly

What the sandbox is not

  • Not a real health plan, and not a place for real patient data: anything sent is visible to other testers. Use invented people only.
  • Not a guarantee about any real payer. Each plan has its own rules and its own documentation; passing here means your client speaks the standards, not that a given plan will approve.
  • Not certification. Perfuse is tested with Inferno in public; nothing here is an ONC certification or a CAQH CORE certification.
  • Shared and limited: writes are capped at 300 a minute from one address, and what testers send may be cleared when the server is upgraded.
  • Want the same thing on your own computer or network? Download Perfuse, free under Apache 2.0, and load the same rules with deploy/test-instance from the repository.
