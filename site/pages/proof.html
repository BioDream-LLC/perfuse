Proof

How Perfuse is tested, and what the tests found

A test that only checks Perfuse against itself proves little. Perfuse is tested against the official conformance suites and against the real software it talks to, and the results, failures included, are published.

Inferno

The official FHIR test kits, run in public

What it is

Inferno is the testing tool ONC and HL7 publish for FHIR servers. Its test kits check a server against each implementation guide, request by request.

Why it matters

CMS points payers to the Da Vinci guides; Inferno is how anyone checks a server follows them.

How to check it yourself

Open inferno.healthit.gov, choose a kit, and point it at test.perfuse.health. The settings we use are in the repository.

What is left

Every remaining failure, explained

Where a failure is the test kit's rather than Perfuse's, the upstream report is linked. None is hidden by leaving a test out.

PAS, 2 fail

The kit asks for must-support extensions on ClaimResponse that the extensions' own definitions do not allow there, so a valid resource cannot carry them. Reported upstream: davinci-pas-test-kit #11.

DTR, 2 fail

The same kind of finding in DTR's kit, fixed upstream and waiting for a release: davinci-dtr-test-kit #130.

Plan-Net, 10 fail

The kit picks the value for a chained search from the first organization it has seen, not one the searched resources refer to, so the search rightly finds nothing. davinci-plan-net-test-kit #34.

CRD, DTR and PAS 2.1.0

No Inferno kit tests 2.1.0, the release CMS-0057 points at now. Each 2.1.0 guide's own example requests were sent to Perfuse and its answers checked by the HL7 validator against 2.1.0: no errors in them. The run and every result.

PDex, 1 skip

A list of elements the guide asks for that cannot appear in a resource that also passes the same guide's profile.

Be honest about it

What has not been proven

Perfuse has not yet run in production at a hospital or health plan. Every test above used test data. We say so here because it is the first thing a careful buyer should ask, and the answer should be easy to find.

The public test server

test.perfuse.health runs the FHIR, CRD, DTR, PAS, Bulk Data and SMART endpoints with test data only, and is checked every half hour. Sign in to the console with username demo and password try-perfuse-demo: it can look at everything and change nothing.
