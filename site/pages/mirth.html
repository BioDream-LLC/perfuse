Leaving Mirth Connect

A free alternative to Mirth Connect that runs your channels

From version 4.6, Mirth Connect is commercial only. Perfuse is free under Apache 2.0, reads your Mirth exports, runs your existing JavaScript unchanged, and runs beside Mirth on your real traffic until you can prove the two agree.

The usual blocker

E4X runs here

Mirth transformers are JavaScript, and many use E4X, the syntax that lets a script write msg['PID']['PID.5']['PID.5.1']. Modern JavaScript engines removed E4X years ago, so most migrations discover on the first transformer that they are really a rewrite. Perfuse runs E4X, along with channelMap, $(), DateUtil and SerializerFactory.

That is why a Mirth migration here is a conversion, not a rewrite of every transformer you own.

How the move works

Five steps, each one reversible

ICON:eye

1. Explain

perfuse explain server-backup.xml says by name what converts, what converts with caveats, and what does not, before you commit to anything.

ICON:swap

2. Translate

perfuse translate turns a channel, a group, a code template library or a whole server backup into Perfuse channels.

ICON:flask

3. Test

perfuse test runs each channel on sample messages and checks what comes out.

ICON:layers

4. Run beside Mirth

Mirth forwards a copy of live traffic; Perfuse writes its results to a folder and delivers nothing. No patient is affected, so nobody needs to approve it.

ICON:check

5. Prove

perfuse compare pairs the two engines' outputs by message and reports every difference, grouped by cause.

The same tools work for the Open Integration Engine and BridgeLink, the open-source forks of Mirth, and Perfuse can write channels back out as Mirth files, so the door stays open both ways.
