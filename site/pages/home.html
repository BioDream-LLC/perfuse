Monitoring

Know where every message went

Every message is stored as it arrived, before anything changes it. Search by patient, control number, type or content, open any message to see each step it took, and resend it if you need to.

  • Find a patient's messages by typing what you know: a record number, a name, a date of birth
  • Searches HL7 v2, FHIR, DICOM and X12 at once
  • Every search is written to the audit trail

Everything in one program

What Perfuse does

Most sites buy an interface engine, then a FHIR server, then a prior authorization product, then a monitoring tool. Perfuse is all of them, in a single download, with one console to run them from.

ICON:engine

Interfaces that do not lose messages

Receive, check, change and deliver HL7 v2 and more. Each destination has its own queue on disk, and the sender is told "received" only when it is true.
ICON:layers

Build it in the browser

A guided channel builder, declarative steps, JavaScript or Lua when you need it, and a playground to try a change on a real message first.
ICON:plug

Connects to almost anything

MLLP, files, FTP and SFTP, databases, web services, AWS, Azure, Google Cloud, Kafka, MQTT and IBM MQ.

HL7 v2, FHIR R4 and R5, DICOM and DICOMweb, X12 837, 835, 270/271 and 278, C-CDA, and the conversions between them.

Patient Access, Provider Access, Payer-to-Payer and Prior Authorization, plus the provider directory, ready to run.
